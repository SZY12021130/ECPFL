# PAMP方案逻辑闭环审查报告

## 审查结论

**总体判断：方案大逻辑成立，但存在3个关键逻辑漏洞和2个需要明确的假设。**

以下逐条审查方案中每个环节的输入、输出、前提条件是否自洽。

## 二、Phase 1：客户端训练与加密 —— **发现2个漏洞**

### 漏洞1：成对掩码生成不安全 ❌

**当前设计**：
```python
pair_seed = hash((min(i,j), max(i,j)))  # 公开可计算！
r_ij = RNG(pair_seed)  # 任何客户端都能算出所有r_ij
```

**问题**：如果seed是公开函数（仅依赖client ID），那么**任何客户端都可以计算任意一对(i,j)的r_ij**。

后果：
- 客户端k知道r_ik（自己和i的），也知道r_jk（自己和j的）
- 但客户端k**还能算出r_ij**（i和j的）！
- 这意味着客户端k知道了太多成对掩码，可能帮助它推断聚合梯度

**修复方案**：

**方案A：KGC预分发（推荐用于论文）**
```
KGC在初始化时:
  for each pair (i,j):
    r_ij ← U(-B, B)
    KGC → C_i: r_ij
    KGC → C_j: r_ji = -r_ij
```
- KGC离线后，r_ij不再改变
- 每轮使用相同的成对掩码
- 安全性：KGC可信且已离线

**方案B：Diffie-Hellman协商（更标准）**
```
C_i和C_j运行DH:
  k_ij = DH(C_i.secret, C_j.public)
  r_ij = PRF(k_ij), r_ji = -PRF(k_ij)
```
- 只有i和j知道k_ij
- 其他客户端无法计算r_ij
- 需要客户端之间能通信（或通过服务器转发DH消息）

**建议论文采用方案A**（KGC预分发），简洁且安全假设清晰。

---

### 漏洞2：HPCoE分类全局不一致 ❌

**当前设计**：
```python
# 每个客户端独立分类
classification_i = encoder.classify_parameters(gradients_i)
classification_j = encoder.classify_parameters(gradients_j)
```

**问题**：客户端i和客户端j可能对同一参数分类不同。

后果：
- C_i把param_X加密为HIGH (scale=2^40)
- C_j把param_X加密为LOW (scale=2^20)
- 服务器无法聚合（不同scale的密文不能直接相加）

**修复方案**：

**固定分类表（推荐）**
```
初始化时，基于模型架构的元信息（不是网络结构！）生成分类表:
  - 按参数维度大小分类:
    dim < 1K: HIGH (小参数精确重要)
    1K ≤ dim < 100K: MEDIUM
    dim ≥ 100K: LOW (大参数近似可接受)
  
  或按参数类型:
    bias: HIGH (值小，变化敏感)
    weight: 按维度分类
```

- 所有客户端使用**同一个固定分类表**
- 不依赖运行时统计
- 不依赖网络层名（符合密文对齐原则）

## 三、Phase 1：服务器聚合与预取 —— 闭环检查 ✓

| 环节 | 输入 | 处理 | 输出 | 闭环状态 |
|------|------|------|------|---------|
| 聚合 | {ct_i} | Σ ct_i | ct_agg | ✓ |
| Delta | ct_agg^(t), ct_agg^(t-1) | 同态减法 | δ^(t) | ✓ |
| 预取广播 | δ^(t), PrefSet | 广播 | δ^(t) → C_j | ✓ |

**关键等式验证**：

```
ct_agg = Σ_i Enc(pk, g_i + s_i + Σ_j r_ij)
       = Enc(pk, Σ_i g_i + Σ_i s_i + Σ_i Σ_j r_ij)
       = Enc(pk, Σ_i g_i + Σ_i s_i)    [因为 Σ_i Σ_j r_ij = 0]
```

成对掩码抵消闭环：✓（前提：r_ij = -r_ji，且所有客户端诚实执行）

## 四、Phase 2：解密触发 —— **发现1个关键漏洞**

### 漏洞3：去掩过程需要S_cum，但单个客户端无法独立计算 ❌

**当前设计**：
```python
# 客户端k需要S_cum = Σ_i s_i^(latest) - Σ_i s_i^(first)
# 客户端k向其他客户端请求"s_i的份额"
```

**问题**：S_cum = Σ_i s_i 是所有客户端自掩码之和。单个客户端只知道自己的s_k，不知道其他s_i。

** naive修复的问题**：

如果每轮客户端把s_i的Shamir份额发给所有其他客户端：
- 客户端j收到[s_i]_j（i给j的份额）
- 当客户端k请求时，j可以返回[s_i]_k吗？**不行**，j只有[s_i]_j

**正确修复方案**：

**方案A：两阶段份额分发（推荐）**

阶段一（每轮训练后）：
```
每个客户端C_i:
  1. 生成自掩码 s_i
  2. Shamir分片: { [s_i]_1, [s_i]_2, ..., [s_i]_n }
  3. 把 [s_i]_j 发给 C_j (安全通道，如加密消息)
```

阶段二（解密时）：
```
客户端C_k需要S_cum:
  1. C_k已有 [s_i]_k for all i (之前收到的)
  2. C_k计算 [S_agg]_k = Σ_i [s_i]_k    (本地同态！)
  3. C_k广播: "我需要 [S_cum] 的份额"
  4. 其他客户端C_j计算 [S_agg]_j = Σ_i [s_i]_j 并发给C_k
  5. C_k收集≥t个 [S_cum]_j，Shamir重构 S_cum
```

**关键洞察**：Shamir份额是线性的！
```
[S_agg]_j = Σ_i [s_i]_j = Σ_i f_i(j) = (Σ_i f_i)(j) = [Σ_i s_i]_j
```
所以客户端j只需要发一个数 [S_agg]_j，而不是所有[s_i]_j。

**通信量**：每个响应客户端发1个有限域元素（~16字节），非常小。

## 五、阈值解密 —— 闭环检查 ✓（有条件）

| 环节 | 输入 | 处理 | 输出 | 前提条件 |
|------|------|------|------|---------|
| 部分解密 | ct_plain = (c0, c1), sk_i | sk_i · c1 + e_smudge | D_i | ✓ |
| 份额收集 | {D_j}_{j∈T} | — | t个份额 | **≥t个客户端在线** |
| 拉格朗日组合 | {D_j}, {λ_j} | c0 + Σ λ_j · D_j | m | ✓ |
| CKKS解码 | m | Decode(m) | G_cum | ✓ |

**条件**：阈值解密需要 **≥ t 个客户端在线**。

如果在线客户端 < t：
- **无法解密**
- **降级方案**：客户端回退到明文同步（从服务器下载完整模型）

论文需要分析：
- 在典型FL场景中（客户端在线率80%），t = ⌈2n/3⌉时解密成功率
- 降级频率与通信开销的权衡

## 六、HPCoE聚合 —— 闭环检查 ✓（修复后）

修复后的HPCoE：
```
所有客户端使用固定分类表:
  HIGH:  小维度参数 (dim < 1K),   scale=2^40
  MEDIUM: 中维度参数 (1K ≤ dim < 100K), scale=2^30
  LOW:   大维度参数 (dim ≥ 100K),  scale=2^20

聚合:
  ct_agg_HIGH   = Σ_i ct_i_HIGH    (同scale可直接加)
  ct_agg_MEDIUM = Σ_i ct_i_MEDIUM
  ct_agg_LOW    = Σ_i ct_i_LOW
```

闭环：✓（所有客户端对同一参数分类一致）

## 七、安全性分析 —— 闭环检查 ✓（有条件）

| 威胁模型 | 当前分析 | 是否闭环 | 备注 |
|---------|---------|---------|------|
| 半诚实服务器 | 无sk，无法解密 | ✓ | |
| 半诚实客户端（单个） | 1个sk份额不够 | ✓ | |
| 恶意客户端共谋（<t） | Shamir (t-1)-privacy | ✓ | |
| 恶意客户端共谋（≥t） | 可恢复sk | ⚠️ | 需设t=⌈2n/3⌉ |
| 服务器+客户端共谋 | 1个sk份额不够 | ✓ | |
| 恶意服务器（伪造delta） | delta是密文，无法分析 | ⚠️ | 但可导致模型发散 |

**需要补充**：
1. **去签名后的delta伪造**：虽然delta是密文，但服务器可以给不同客户端发不同delta。这不会泄露明文，但会导致**模型分叉**（不同客户端看到不同的全局模型）。
   - 缓解：客户端之间定期交换聚合结果的哈希（轻量级一致性检查）

2. **重放攻击**：服务器重放过期delta。
   - 缓解：delta包含轮次号，客户端只接受轮次号递增的delta（无需签名，只需单调性检查）

## 九、修复后的完整逻辑链

```
Phase 0:
  KGC生成 (pk, sk, evk)
  KGC生成所有成对掩码 r_ij, r_ji = -r_ij
  KGC分发: sk_i→C_i, r_ij→C_i, pk/evk→AS
  KGC离线

Phase 1 (每轮):
  C_i:
    1. g_i ← LocalTrain()
    2. s_i ← U(-B, B)
    3. m_i = s_i + Σ_j r_ij
    4. Shamir分片: { [s_i]_j } → 发给 C_j
    5. 按固定分类表HPCoE编码
    6. ct_i = Enc(pk, g_i + m_i; 按类scale)
    7. 上传 ct_i 到 AS

  AS:
    8. 按精度类分别聚合: ct_agg = Σ ct_i
    9. δ = ct_agg^(t) - ct_agg^(t-1)
    10. 广播 δ → 未选中客户端

  C_j (未选中):
    11. ct_prefetch += δ

Phase 2 (C_k被选中且ct_prefetch≠∅):
  C_k:
    12. 广播: "请求 [S_cum] 份额"
    13. 每个在线C_j: 计算 [S_cum]_j = Σ_i [s_i]_j, 发给 C_k
    14. C_k收集≥t个份额，Shamir重构 S_cum
    15. ct_plain = ct_prefetch - Enc(pk, S_cum) = Enc(pk, G_cum)
    16. P2P阈值解密 ct_plain:
         - C_k算 D_k = sk_k · c1 + e_smudge
         - 收集 t-1 个其他客户端的 D_j
         - G_cum = Decode(c0 + Σ λ_j · D_j)
    17. w_sync = w_base + lr · G_cum
    18. 训练
```

## 十、修复清单

| # | 漏洞 | 严重度 | 修复方案 | 论文中如何说明 |
|---|------|--------|---------|--------------|
| 1 | 成对掩码公开可计算 | **高** | KGC预分发 | 安全假设：KGC通过安全通道分发成对掩码 |

| 3 | 去掩需要P2P份额 | **中** | 两阶段Shamir分发 | 客户端之间通过加密消息交换份额，服务器只转发密文 |

| 5 | 无签名导致delta伪造 | **低** | 轮次单调性检查 | 客户端拒绝轮次号≤last_accepted的delta |

## 十一、最终结论

**方案逻辑闭环：成立（修复后）**

PAMP方案的核心逻辑是严密的：
1. **PCCM掩码**在聚合时正确抵消，个体梯度被完全隐藏
2. **延迟去掩**确保预取阶段始终处于密文保护状态
3. **P2P阈值解密**无需额外辅助节点
4. **HPCoE**提升打包效率（修复分类一致性问题后）

**3个关键修复必须在论文和代码中落实**：
1. 成对掩码由KGC安全预分发（或DH协商）
2. HPCoE使用全局固定的基于参数维度的分类表
3. Shamir份额通过两阶段分发支持去掩

修复后，方案在6种威胁模型下均有形式化安全保证，且训练准确率与FedAvg等价。
