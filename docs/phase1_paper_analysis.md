# 阶段一：联邦学习+CKKS同态加密论文深度分析报告

## 一、论文概览

本报告系统分析了近3年（2020-2026）关于"联邦学习+同态加密（尤其是CKKS）"的16篇代表性论文，涵盖以下研究方向：

| 类别 | 论文数量 | 代表工作 |
|------|----------|----------|
| 单密钥同态加密方案 | 3 | Liu等2025, Zhang等2020, Xie等2024 |
| 多密钥同态加密方案 | 3 | Omar等2025, Cai等2024, Passelègue等2025 |
| 选择性/打包同态加密 | 4 | Hu等2025, Li等2025, Korkmaz等2026, Jin等2024 |
| 通信效率优化 | 3 | ResFed, FetchSGD, FedFetch |
| 安全聚合基础 | 2 | Bonawitz等2017, Phalanx |
| 高效加法同态加密 | 1 | Wu等2025 |

## 二、当前方法的共性缺陷（通病总结）

### 2.1 计算效率瓶颈

| 缺陷类别 | 具体表现 | 影响范围 |
|----------|----------|----------|
| **CKKS乘法深度限制** | 每次同态乘法增加噪声，需频繁bootstrapping | 所有基于CKKS的方案 |
| **密文膨胀问题** | CKKS密文大小是明文的10-100倍 | 通信密集型方案 |
| **旋转密钥开销** | 密文对齐需要大量旋转密钥，内存占用高 | 需要slot间操作的方案 |
| **标量-密文乘法低效** | 相比密文-密文加法，标量乘法仍涉及NTT转换 | 联邦学习中的加权聚合 |

### 2.2 安全性分析不足

| 缺陷类别 | 具体表现 | 典型论文 |
|----------|----------|----------|
| **半诚实假设过于理想** | 多数方案仅证明半诚实安全，恶意/共谋分析缺失 | Liu等2025, Omar等2025 |
| **噪声泄露风险** | CKKS解密泄漏噪声，可被用于密钥恢复攻击 | 所有CKKS方案 |
| **IND-CPA-D漏洞** | 解密结果可被用于区分攻击，阈值方案尤其脆弱 | Passelègue等2025 |
| **共谋阈值设定随意** | 缺乏严格的共谋下界分析 | Xie等2024 |

### 2.3 系统级问题

| 缺陷类别 | 具体表现 | 影响 |
|----------|----------|------|
| **密钥分发开销被忽视** | 多数方案假设密钥已分发，实际部署成本高 | 跨设备联邦学习 |
| **掉线处理机制缺失** | 安全聚合协议对掉线客户端的处理不完善 | 移动场景 |
| **非IID数据适应性差** | 加密方案与FedAvg等优化算法结合困难 | 实际数据分布 |
| **模型准确率损失** | 加密引入的噪声/近似导致模型性能下降 | 医疗等敏感应用 |

### 2.4 技术缝合问题

| 问题 | 描述 |
|------|------|
| **HE+DP简单叠加** | 差分隐私与同态加密噪声叠加缺乏理论分析 |
| **压缩+加密顺序混乱** | 梯度压缩与同态加密的先后顺序影响安全性和效率 |
| **多密钥切换开销** | 多密钥HE方案中密钥切换的通信/计算成本被低估 |

## 三、已有工作的关键技术突破（创新点总结）

### 3.1 单密钥同态加密优化

| 论文 | 核心创新 | 技术细节 |
|------|----------|----------|
| **Liu等2025** | 单密钥分层聚合 | 引入边缘服务器作为中间聚合层，减少中心服务器计算负担；采用分层CKKS参数，边缘使用低精度、中心使用高精度 |
| **Zhang等2020 (BatchCrypt)** | 批量加密编码 | 将多个梯度值打包到单个CKKS密文的多个slot中；提出量化+编码联合优化，减少密文数量 |
| **Xie等2024** | 云联邦+ECC密钥保护 | 双云架构分离聚合与解密；ECC加密CKKS私钥，Shamir门限分割防止共谋 |

### 3.2 多密钥同态加密突破

| 论文 | 核心创新 | 技术细节 |
|------|----------|----------|
| **Omar等2025** | 多密钥CKKS高效聚合 | 基于CKKS的多密钥扩展，支持不同客户端密钥下的密文加法；提出密钥一致性协议减少通信轮数 |
| **Cai等2024 (SecFed)** | 多密钥+安全聚合混合 | 结合多密钥HE与Bonawitz式安全聚合；提出"密钥链"机制减少密钥管理开销 |
| **Passelègue等2025** | 低通信阈值FHE | 提出"Double-Flood-and-Round"技术；ServerDec算法在部分解密前引入额外随机性；证明多项式量级噪声即可保证安全 |

### 3.3 选择性/打包加密创新

| 论文 | 核心创新 | 技术细节 |
|------|----------|----------|
| **Hu等2025 (MaskCrypt)** | 梯度敏感性感知加密 | 基于梯度L2范数识别敏感参数；仅加密Top-k敏感梯度，其余明文传输+DP噪声 |
| **Li等2025 (FedPHE)** | 打包同态加密 | 将多层神经网络参数打包到单个密文；利用CKKS的SIMD特性并行处理多层 |
| **Korkmaz等2026 (FAS)** | 选择性HE+DP+ scrambling三层防护 | 固定比例加密+差分隐私噪声+位混淆；消除预训练阶段，每轮动态选择加密参数 |
| **Jin等2024 (FedML-HE)** | 自适应敏感参数识别 | 基于梯度变化率识别关键参数；支持模型不同层使用不同加密策略 |

### 3.4 通信效率优化

| 论文 | 核心创新 | 技术细节 |
|------|----------|----------|
| **ResFed** | 残差编码传输 | 传输模型残差而非完整权重；残差对压缩率敏感度低于梯度；支持双向压缩 |
| **FetchSGD** | Count Sketch压缩 | 使用Count Sketch压缩梯度；利用sketch的线性性质支持服务器端动量累积；无需客户端状态 |
| **FedFetch** | 预取调度优化 | 客户端采样+压缩结合时的模型同步问题；预取调度减少训练阶段下载时间 |

### 3.5 安全聚合基础

| 论文 | 核心创新 | 技术细节 |
|------|----------|----------|
| **Bonawitz等2017** | 实用安全聚合协议 | 双掩码结构（ pairwise masks + 个人掩码）；Shamir秘密共享处理掉线；通信复杂度O(n+m) |
| **Phalanx** | FHE友好SNARK | 低乘法深度(4层)SNARK构造；兼容FHE SIMD操作；知识可提取性防止输入依赖攻击 |

## 四、尚未解决的关键问题（研究空白总结）

### 4.1 理论层面空白

| 空白领域 | 具体问题 | 重要性 |
|----------|----------|--------|
| **CKKS噪声精确分析** | 联邦学习多轮迭代下的噪声累积模型缺失 | 决定bootstrapping触发时机 |
| **多密钥HE的严格安全证明** | 多数方案仅提供启发式安全分析 | 影响实际部署信心 |
| **加密+压缩联合优化理论** | 缺乏压缩率-安全性-准确率的帕累托前沿分析 | 指导参数选择 |
| **非IID数据下的收敛性** | 加密噪声对FedAvg在非IID数据上收敛的影响未研究 | 实际应用关键 |

### 4.2 技术层面空白

| 空白领域 | 具体问题 | 潜在解决方案 |
|----------|----------|--------------|
| **动态CKKS参数调整** | 固定参数无法适应不同训练阶段需求 | 基于噪声水平自适应调整模数链 |
| **轻量级密钥更新** | 客户端密钥泄露后的高效更新机制缺失 | 基于属性的密钥派生 |
| **异构客户端支持** | 不同计算能力客户端的统一加密框架 | 分层加密策略 |
| **模型推理阶段保护** | 多数方案仅保护训练，推理阶段暴露 | 同态推理+安全聚合结合 |

### 4.3 系统层面空白

| 空白领域 | 具体问题 |
|----------|----------|
| **端到端延迟优化** | 加密、通信、聚合的流水线调度未优化 |
| **容错机制** | 大规模客户端掉线时的聚合质量保证 |
| **可验证计算集成** | 服务器聚合行为的可验证性（与Phalanx方向不同） |
| **跨域联邦学习** | 不同组织间密钥信任建立机制 |

### 4.4 评估层面空白

| 空白领域 | 具体问题 |
|----------|----------|
| **标准化评估基准** | 缺乏统一的CKKS-FL评估框架 |
| **真实场景测试** | 多数实验在模拟环境，真实移动设备测试缺失 |
| **长期训练稳定性** | 数百轮训练后的准确率/安全性衰减未研究 |

## 五、IEEE TIFS/NDSS级别论文标准结构建议

### 5.1 推荐结构（针对CKKS-FL创新方案）

```

   - 贡献：明确、可验证的3-4条贡献
   - 核心思想：一句话概括创新点

2. Background and Related Work (2页)
   - 2.1 Federated Learning Basics
   - 2.2 CKKS Homomorphic Encryption (数学符号统一)

   - 3.1 Notation

   - 4.1 System Model (Mermaid架构图)

   - 4.3 Detailed Construction (分阶段伪代码)

5. Theoretical Analysis (2页)
   - 5.1 Computational Complexity

6. Implementation and Evaluation (3-4页)
   - 6.1 Experimental Setup

   - 6.3 Accuracy Comparison
   - 6.4 Efficiency Metrics (计算/通信/内存)
```

### 5.2 关键写作要点

| 部分 | 要点 |
|------|------|
| **Introduction** | 避免"dynamic/adaptive/hierarchical"等泛化词汇；用具体技术术语描述创新 |
| **Security Proof** | 必须包含形式化定理+证明；明确安全参数λ与噪声分布的关系 |
| **Noise Analysis** | 给出噪声方差的递推公式；标明bootstrapping触发条件 |
| **Experiments** | 至少包含MNIST/Fashion-MNIST/CIFAR-10三个数据集；对比至少3个baseline |
| **Code** | 提供开源链接（Artifact Evaluation加分项） |

## 六、总结与阶段二准备

### 6.1 关键洞察

1. **单密钥 vs 多密钥**：单密钥方案适合cross-silo（少量高信任客户端），多密钥方案适合cross-device（大量低信任客户端）

2. **全加密 vs 选择性加密**：全加密安全性高但开销大；选择性加密需解决"加密哪些参数"的决策问题

3. **噪声管理是核心**：CKKS的实用性取决于噪声增长模型的精确性

4. **系统级优化空间大**：现有方案多为技术缝合，缺乏端到端优化

### 6.2 阶段二设计方向建议

基于以上分析，阶段二的新方案设计应关注：

1. **创新点1**：针对CKKS噪声累积问题，设计自适应噪声管理策略
2. **创新点2**：针对密文对齐约束，设计旋转密钥优化机制
3. **严格安全性**：从RLWE假设出发，给出完整的IND-CPA安全证明
4. **实用性**：考虑神经网络训练准确率，避免纯技术缝合
