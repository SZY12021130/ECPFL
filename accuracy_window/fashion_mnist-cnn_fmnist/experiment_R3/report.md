## 5. Communication & Ciphertext Details / 通信与密文计算详情

| 3 | Ciphertext Blocks / 密文块数 | `sum(len(v) for v in encrypted_update.values())` |

### 5.3 Prefetch Communication Analysis / 预取通信分析

- **Total Upload / 总上传开销:** 2630.15 MB — 所有选中客户端密文上传的累计量
- **Fetch Volume (FV) / 补下载量:** 27.16 MB — 选中客户端实际 fetch 下载量（已扣除预取覆盖部分）
- **Training Communication (TV) / 训练通信:** 2657.31 MB = Upload(2630.15 MB) + FV(27.16 MB)
  ✅ 验证通过: Upload(2630.15 MB) + FV(27.16 MB) = TV(2657.31 MB)
  — TV 对齐 FedFetch 论文定义：TV = Upload + FV（不含后台预取）
- **Prefetch Broadcast / 预取广播:** 3478.65 MB — 服务器向未选中客户端后台广播的密文增量
- **Prefetch Download / 预取下载:** 3478.65 MB — 未选中客户端后台接收的密文增量
- **Prefetch + Fetch + Broadcast / 后台总流量:** 6984.46 MB = Prefetch DL(3478.65) + Fetch DL(27.16) + Broadcast(3478.65)
- **Effective Download / 理论下载责任:** 190.78 MB — 每轮 delta_size × 选中客户端数（预取节省率计算基准）
- **Prefetch Savings / 预取节省:** 163.62 MB — Effective Download 与实际 FV 的差值
- **Baseline (no prefetch) / 无预取基线:** 190.78 MB — 完整模型下载(0.15 MB × 1250 次)

> **Note / 说明:**
> 1. **FV** = 选中客户端实际 fetch 下载量。TV = Upload + FV（FedFetch 论文定义）。
> 2. **Effective Download** = delta_size × 选中客户端数，是理论下载责任，仅用于计算预取节省率。
> 3. **Prefetch** = 后台/空闲时流量，不计入 TV，但计入物理总下行带宽。
> 4. 预取的核心优势是**将训练前的同步下载变为后台增量推送**，降低 wall-clock 延迟。

## 6. Conclusion / 结论

- **Privacy / 隐私性:** 本实验采用 **CKKS 同态加密** 实现隐私保护联邦学习，服务器始终无法访问客户端原始模型更新。
- **Accuracy / 准确率:** 经过 **50** 轮训练，最终测试准确率达到 **89.75%**，测试损失为 **0.2943**。
- **Communication Overhead / 通信开销:** CKKS 密文引入 **13.79x** 的通信膨胀率。
- **Encryption Cost / 加密开销:** 平均每轮每个客户端加密耗时 **0.032s**。
- **Prefetch / 预取优化:** 启用 **CipherFetch (FedFetch-style)** 密文预取机制。
- **Training Communication / 训练通信:** 总训练通信 **2721083.63 KB**（上传 2693269.34 KB + 下载 27814.29 KB）。
- **Download Saved / 节省下载:** 选中客户端避免完整模型下载，共节省 **167547.03 KB**.
