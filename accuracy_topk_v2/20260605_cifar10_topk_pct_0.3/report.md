## 5. Communication & Ciphertext Details / 通信与密文计算详情

| 2 | Ciphertext Size / 密文大小 | `sum(len(ct.serialize()) for ct in encrypted_update.values())` |
| 3 | Ciphertext Blocks / 密文块数 | `sum(len(v) for v in encrypted_update.values())` |

### 5.3 Prefetch Communication Analysis / 预取通信分析

- **Total Upload / 总上传开销:** 8368.59 MB — 所有选中客户端密文上传的累计量
- **Fetch Volume (FV) / 补下载量:** 182.04 MB — 选中客户端实际 fetch 下载量（已扣除预取覆盖部分）
- **Training Communication (TV) / 训练通信:** 8550.63 MB = Upload(8368.59 MB) + FV(182.04 MB)
  ✅ 验证通过: Upload(8368.59 MB) + FV(182.04 MB) = TV(8550.63 MB)
  — TV 对齐 FedFetch 论文定义：TV = Upload + FV（不含后台预取）
- **Prefetch Broadcast / 预取广播:** 11181.51 MB — 服务器向未选中客户端后台广播的密文增量
- **Prefetch Download / 预取下载:** 11181.51 MB — 未选中客户端后台接收的密文增量
- **Prefetch + Fetch + Broadcast / 后台总流量:** 22545.07 MB = Prefetch DL(11181.51) + Fetch DL(182.04) + Broadcast(11181.51)
- **Effective Download / 理论下载责任:** 1306.73 MB — 每轮 delta_size × 选中客户端数（预取节省率计算基准）
- **Prefetch Savings / 预取节省:** 1124.69 MB — Effective Download 与实际 FV 的差值
- **Baseline (no prefetch) / 无预取基线:** 1306.73 MB — 完整模型下载(1.05 MB × 1250 次)

> **Note / 说明:**
> 1. **FV** = 选中客户端实际 fetch 下载量。TV = Upload + FV（FedFetch 论文定义）。
> 2. **Effective Download** = delta_size × 选中客户端数，是理论下载责任，仅用于计算预取节省率。
> 3. **Prefetch** = 后台/空闲时流量，不计入 TV，但计入物理总下行带宽。
> 4. 预取的核心优势是**将训练前的同步下载变为后台增量推送**，降低 wall-clock 延迟。

## 6. Conclusion / 结论

- **Privacy / 隐私性:** 本实验采用 **CKKS 同态加密** 实现隐私保护联邦学习，服务器始终无法访问客户端原始模型更新。
- **Accuracy / 准确率:** 经过 **50** 轮训练，最终测试准确率达到 **67.92%**，测试损失为 **0.8872**。
- **Communication Overhead / 通信开销:** CKKS 密文引入 **6.40x** 的通信膨胀率。
- **Encryption Cost / 加密开销:** 平均每轮每个客户端加密耗时 **0.157s**。
- **Prefetch / 预取优化:** 启用 **CipherFetch (FedFetch-style)** 密文预取机制。
- **Training Communication / 训练通信:** 总训练通信 **8755842.88 KB**（上传 8569431.11 KB + 下载 186411.77 KB）。
- **Download Saved / 节省下载:** 选中客户端避免完整模型下载，共节省 **1151683.93 KB**.
