### 5.3 Prefetch Communication Analysis / 预取通信分析

- **Total Upload / 总上传开销:** 1195.51 MB — 所有选中客户端密文上传的累计量
- **Fetch Volume (FV) / 补下载量:** 21.55 MB — 选中客户端实际 fetch 下载量（已扣除预取覆盖部分）
- **Training Communication (TV) / 训练通信:** 1217.05 MB = Upload(1195.51 MB) + FV(21.55 MB)
  ✅ 验证通过: Upload(1195.51 MB) + FV(21.55 MB) = TV(1217.05 MB)
  — TV 对齐 FedFetch 论文定义：TV = Upload + FV（不含后台预取）
- **Prefetch Broadcast / 预取广播:** 1588.73 MB — 服务器向未选中客户端后台广播的密文增量
- **Prefetch Download / 预取下载:** 1588.73 MB — 未选中客户端后台接收的密文增量
- **Prefetch + Fetch + Broadcast / 后台总流量:** 3199.00 MB = Prefetch DL(1588.73) + Fetch DL(21.55) + Broadcast(1588.73)
- **Effective Download / 理论下载责任:** 190.78 MB — 每轮 delta_size × 选中客户端数（预取节省率计算基准）
- **Prefetch Savings / 预取节省:** 169.24 MB — Effective Download 与实际 FV 的差值
- **Baseline (no prefetch) / 无预取基线:** 190.78 MB — 完整模型下载(0.15 MB × 1250 次)

> **Note / 说明:**
> 1. **FV** = 选中客户端实际 fetch 下载量。TV = Upload + FV（FedFetch 论文定义）。
> 2. **Effective Download** = delta_size × 选中客户端数，是理论下载责任，仅用于计算预取节省率。
> 3. **Prefetch** = 后台/空闲时流量，不计入 TV，但计入物理总下行带宽。
> 4. 预取的核心优势是**将训练前的同步下载变为后台增量推送**，降低 wall-clock 延迟。

## 6. Conclusion / 结论

- **Privacy / 隐私性:** 本实验采用 **CKKS 同态加密** 实现隐私保护联邦学习，服务器始终无法访问客户端原始模型更新。
- **Accuracy / 准确率:** 经过 **50** 轮训练，最终测试准确率达到 **86.14%**，测试损失为 **0.3967**。
- **Communication Overhead / 通信开销:** CKKS 密文引入 **6.27x** 的通信膨胀率。
- **Encryption Cost / 加密开销:** 平均每轮每个客户端加密耗时 **0.023s**。
- **Prefetch / 预取优化:** 启用 **CipherFetch (FedFetch-style)** 密文预取机制。
- **Training Communication / 训练通信:** 总训练通信 **1246261.03 KB**（上传 1224197.67 KB + 下载 22063.36 KB）。
- **Download Saved / 节省下载:** 选中客户端避免完整模型下载，共节省 **173297.97 KB**.
