Abstract—Federated Learning (FL) is widely used in various in-
dustries because it effectively addresses the predicament of isolated
data island. However, eavesdroppers is capable of inferring user
privacy from the gradients or models transmitted in FL. Homomor-
phic Encryption (HE) can be applied in FL to protect sensitive data
owing to its computability over ciphertexts. However, traditional
HE as a single-key system cannot prevent dishonest users from in-
tercepting and decrypting the ciphertexts from cooperative users in
FL. Guaranteeing privacy and efﬁciency in this multi-user scenario
is still a challenging target. In this article, we propose a secure and
efﬁcient Federated Learning scheme (SecFed) based on multi-key
HEtopreserveuserprivacyanddelegatesomeoperationstoTEEto
improve efﬁciency while ensuring security. Speciﬁcally, we design
the ﬁrst TEE-based multi-key HE cryptosystem (EMK-BFV) to
support privacy-preserving FL and optimize operation efﬁciency.
Furthermore,weprovideanofﬂineprotectionmechanismtoensure
the normal operation of system with disconnected participants.
Finally, we give their security proofs and show their efﬁciency and
superiority through comprehensive simulations and comparisons
with existing schemes. SecFed offers a 3x performance improve-
ment over TEE-based scheme and a 2x performance improvement
over HE-based solution.
Index Terms—Federated learning, homomorphic encryption,
privacy preservation, trusted execution environment.

II. BACKGROUND AND RELATED WORK
Different from centralized ML, FL enables involved users
to exchange gradients or models rather than raw data for
collaborative training, which solves the issue of isolated data
island. But there still exist some attacks towards the gradients
or models [11]. Some research have been conducted to further
enhance the security and privacy of user data and models in FL.
A. SMC-Based Federated Learning
SMC enables users to jointly compute a model or a function
over their inputs while keeping those inputs private [12]. SMC
technique can be applied to implement secure transmission and
aggregation of gradients or models. While work [13] revealed
the fact that it is difﬁcult for secure aggregation to ensure privacy
integrity in the presence of malicious servers. But there are
still some works that proposed solutions based on semi-trusted
servers. Bonawitz et al. [14] ﬁrst constructed the SMC protocol
to achieve secure aggregation, and the authors constructed a
privacy computation process using double-masking. However,
the users involved in the SMC protocol have to communicate
and connect with all other users, which is inefﬁcient. Bell
et al. [15] improved on work [14] by modifying the way users
communicate with each other. Instead of needing to commu-
nicate with other N −1 users, a particular user communicates
with log(N) users. However this reduction in communication
overhead is achieved by maintaining new data structures, which
introduces additional storage overhead. The work [16] achieved
secureaggregationofgradientsthroughsecretsharing.However,
it comes with additional communication rounds that exchange
necessary parameters for secure aggregation. These additional
communications severely affect the model convergence speed
in case of a poor communication environment. FATE [17] used
masking techniques to protect model, in which users need to
negotiate between themselves to generate masks. The interre-
lated masks ensure the security of model aggregation and the
correctness of decryption. But FATE introduces the overhead
of masking generation and prolongs running time for users with
constrained resources. Moreover, any loss of mask will cause the
decryption to fail. These indicate that SMC-based FL schemes
have certain disadvantages in terms of communication overhead
and user computation overhead.
B. DP-Based Federated Learning
DP preserves privacy by adding noise to personal sensitive
data[18].TherearetwomethodstoapplyDPtoFLforprotecting
users’ data. One approach is to add noise to user’s dataset before
local training, such as DPFedAvg-GAN [19] and NbAFL [20].
These schemes used dataset with noise to train model, thus
making it impossible for attackers to infer dataset from model.
However, the noise negatively affects the convergence speed of
the model and degrades the model accuracy. Another way is
adding noise to parameters in model or directly to gradients on
the user side. Abidi et al. [21] added noise to model iteration to
protect the privacy dataset. However, the FL aggregation process

C. TEE-Based Federated Learning
TEE spends extra time to create and maintain a secure envi-
ronment for programs running by encrypting memory. As in
scheme [23] and [24], secure memory ensured data privacy,
but introduced additional overhead. In work [23], the authors
used TEE to protect the prediction process, which avoided
moving the complex training process into secure memory. How-
ever, too much prediction data will seriously increase the time
overhead. Modal et al. [24] migrated the aggregation process
of FL into TEE for execution, which protected user privacy.
But the frequent data interactions between memories lead to a
dramatic increase in the cost of secure memory, which incurs a
larger time overhead. In order to avoid excessive use of secure
memory in schemes [23] and [24], Fan et al. [25] used a greedy
algorithm to optimize the model to make TEE handle less data
and avoided expensive paging mechanism. However, the use of
greedy algorithm increases the computation overhead of the reg-
ular part of the program and does not achieve signiﬁcant results.
In summary, how to use TEE reasonably to avoid additional
time overhead and to achieve a balance between efﬁciency and
security remains an important challenge.
D. HE-Based Federated Learning
HE provided the capability of computation over ciphertexts,
which had been widely applied in FL for protecting data privacy.
Based on the number of keys used in HE, we could classify them
into single-key HE-based FL schemes and multi-key HE-based
FL. They achieved privacy protection to some extent, but there
are still some privacy issues to be solved.
1) FL Based on Single-Key HE: Some existing work simply
applied single-key HE for outsourcing the gradients or models.
Paillier cryptosystem as a popular additive homomorphic en-
cryption is widely used for protecting gradients or models in hor-
izontal FL. Yang et al. [26] used Paillier to protect models while
utilized FPGA to optimize the encryption, thus improving the
operational efﬁciency of HE-based schemes. BatchCrypt [27]
proposed an encoding method that could carry more messages,
enabling Paillier to encrypt more gradients information at one
time. Madi et al. [28] proposed veriﬁable privacy-preserving FL
using Paillier to protect gradients, in which the homomorphic
nature of HE was used to perform ciphertext computation and
authentication of server operations. Stripelis et al. [29] then used
the CKKS cryptosystem [30] to protect model. In vertical FL,
Wei et al. [31] utilized HE to protect the transmission of fea-
tures between users and server, and realized a secure federated
bayesian algorithm based on the vertical distribution of data.

partial decryption results could be aggregated for obtaining the

A. Design of EMK-BFV
To satisfy the requirements of multi-user scenario, we ﬁrst re-
construct an efﬁcient multi-key homomorphic encryption based
on BFV cryptosystem: EMK-BFV. In Fig. 4, we present the
differences of traditional BFV and our EMK-BFV. The detailed
structure of EMK-BFV are as follows:
1) Key Generation: We ﬁrst design multi-key generation
algorithm to meet the challenges in multi-user scenarios while
achieving key conﬁdentiality. We construct four functions:
secretGen(), skGen(), rkGen(), pkGen() and perform them
in TEE to generate keys for users. Algorithm 1 shows the
execution of each function.

V. SECURITY ANALYSIS AND PERFORMANCE EVALUATION
A. Security Analysis
In this subsection, we analyze the security of EMK-BFV and
SecFed. The security of SecFed is guaranteed by EMK-BFV.
Our security analysis is based on the assumption that TEE is
completely trustworthy. Therefore, we did not perform a security
analysis for the data structures and operations in secure memory.
Deﬁnition 1: RLWE problem: Given a uniformly generated
random polynomial a ∈Rq, s ∈Rq and e ∈Rq (e obeys the
distribution ξ). Distinguish (a, a · s + e) from (a, x), where x
is randomly selected.

B. Performance Evaluation
In this section, we tested and evaluated the performance of
EMK-BFV and SecFed, respectively. Furthermore, a series of
comparative tests were conducted to demonstrate performance.
1) Methodology: We implement our scheme and test their
performance with the following settings:
Hardware Setting: The evaluation are performed on a desk-
top with 11th Gen Intel(R) Core(TM) i7-11700 @ 2.50 GHz
processor and 32 GB of running memory. In addition, NVIDIA
GeForce GTX 1650 SUPER is also used to speed up the model
training process in FL.
OS and Software Setting: We use Ubuntu Server 18.04 LTS
as CS operating system and Ubuntu 18.04 LTS as user operating
system. We construct EMK-BFV based on the crypto library
Mircosoft SEAL [40] with version 3.7.
TEE Setting: We use Intel SGX as TEE technology for testing,
which provides a secure area in memory called Enclave for
running functions in SecFed. The SGX driver version is 2.11
while SGX SDK version 2.12. Side-channel attacks [41], [42]
have the potential to result in privacy leakage of data in SGX.
But some countermeasures (such as noise injection [43]) are also
proposed, which can be used in SecFed. Herein, we conducted
an experiment to show the effectiveness of noise injection to
weaken the side-channel attack in SecFed. In this experiment,
we randomly reiterate speciﬁc functions without storing the
results as stabilizer, effectively ensuring a sustained level of
power consumption. As shown in Fig. 7, by repeating the exe-
cution of some functions, it is possible to stabilize the processor
16 cores power within a certain range. Although this method

VI. CONCLUSION
In this paper, we utilized TEE to design SecFed, an efﬁcient
and secure federated learning framework in multi-user scenar-
ios. We designed a secure multi-key homomorphic encryption
cryptosystem based on TEE to preserve user privacy and data
security. In order to solve the problem of user ofﬂine, we pro-
posed an ofﬂine protection mechanism to ensure collaborated
training normally. Security analysis and performance evalua-
tion demonstrate SecFed’s security and efﬁciency. In practical
applications, the features of SecFed match cross-silo FL, which
contains large-scale data-holders. SecFed has a better perfor-
mance in cross-silo FL compared to cross-device FL which
has data-holders with small amount of data and need multiple
encryptions. In the future, we will further improve the efﬁciency
of SecFed and explore signiﬁcant applications.
