## 各列单位与计算方法

| 列 | 单位 | 计算方法 | 来源 |
|---|---|---|---|
| **AC** | %（测试精度） | 第 50 轮全局模型在测试集上的精度 | ECPFL：`ecpfl_results.json → final_test_acc`；ESAFL：`metrics.json → test_acc[-1]`；基线：论文表三旧值 ⚠️ |
| **UV** | MB（10⁶ 字节，50 轮累计） | 50 轮**加密上行**总量。ECPFL=Σₜ upload_bytes（含每客户端每轮 1 个投票密文）；ESAFL=Σ upload_cost；基线=旧表四每轮 UV(MiB)×50×1.048576 | ECPFL/ESAFL 自动读数 ✅；基线 ⚠️ |
| **FV** | MB（10⁶ 字节，50 轮累计） | 50 轮**同步下行 fetch**总量。ECPFL=Σₜ download_bytes（仅当轮缺失包）；基线=旧表四每轮 FV(MiB)×50×1.048576（无预取，下行=聚合包广播全量） | 同上。⚠️ FedAvg 疑点：论文 FV=UV（对称），但 `result_fix_pro` 实测下行只有 0.71×UV——论文 FV 口径与实测不符，待重跑确认 |
| **PV** | MB（10⁶ 字节，50 轮累计） | 50 轮**后台预取**总量（空闲时间传输，不计入 TV）；基线无预取记 "—"。注：PV 与 FV 是**两组不相交的包**——PV = 客户端缺席轮后台预取的历史包（补课聚合，式 16-17），FV = 活跃轮同步下载的当轮新聚合包（聚合前不存在、无法预取）。总量相等是恒等式：50 客户端分两组各 25 人严格隔轮交替，每轮包集合恰好被下载两次（当轮 25 人同步拉 = FV；下一轮 25 人预取 = PV），逐轮均为 25×K^(t)×31,232 B；**逐客户端 PV≠FV**（如 SVHN-UN：组A PV=1882 ct/FV=1901 ct，组B 镜像）。`cache_hits` 恒 0 属结构性（当轮包不可能命中预取缓存，非预取失效） | ECPFL=Σₜ prefetch_bytes ✅ |
| **TV** | MB（10⁶ 字节，50 轮累计） | **TV = UV + FV（同单位直接相加）**。基线旧数据为 MiB 口径（旧论文的"GB"实为 GiB），已按 ×1.048576 统一换算为 MB(10⁶)；例如 FedAvg MNIST：每轮 87.7 MiB ×50×1.048576 = 4,598.0 MB，TV = 8.56 GiB = 9,196.1 MB | ECPFL=`total_tv_mb` ✅；ESAFL 重跑后计算；基线=旧值换算 ⚠️ |
| **UT** | s（秒，50 轮累计） | 50 轮**最慢客户端上传时间**之和：每轮取 maxᵢ(upload_timeᵢ)（异构带宽模拟），再对 50 轮求和 | ECPFL=`total_ut_sim` ✅；基线口径未核实 ⚠️ |
| **DT** | s（秒，50 轮累计） | 50 轮**最慢客户端下载时间**之和，口径同 UT | ECPFL=`total_dt_sim` ✅；基线 ⚠️ |
| **TT** | s（秒，50 轮累计） | **Σₜ maxᵢ(本地训练ᵢ + 投票ᵢ + 加密ᵢ + UTᵢ + DTᵢ)**——每轮取最慢客户端完整时间线求和；服务端聚合不计入 | ECPFL=`total_tt_sim` ✅；ESAFL=Σ `total_round_time_simulated`（重跑后）；基线 ⚠️ |
| **N_up** | 包/轮（个） | 每轮**实际加密上传 pack 总数**（不含投票密文）。ECPFL=25 客户端×K（+掉线补偿包）；ESAFL=25×⌈d/4096⌉（EP 打包 T=2，logq0=20 → 单 ct 装 4096 值）；FedPHE=25×⌈ζJ⌉；MASER=参数级 50% 剪枝后非空 batch（实测 6.94/5.98/33.96/58.96 包/客户端） | ECPFL=upload_bytes/31232−25 逐轮均值 ✅；ESAFL 由 T=2 打包协议决定 ✅；基线=旧表四（MASER 已逐条验证吻合 ✅） |
| **N_agg** | 包/轮（个） | 每轮**共识聚合 pack 数 K**。ECPFL=投票共识涌现值（TH：得票≥θ·\|S\|；RK：前 ⌈θJ⌉ 名；UN：≥1 票），逐轮波动；ESAFL=⌈d/4096⌉ 固定（= ECPFL 的 J，11/10/67/115）；FedAvg=J；FedPHE/MASER=⌈ζJ⌉ | ECPFL=逐轮 K 均值 ✅；其它由协议/剪枝决定 |

### 数据可信度分级

- ✅ **确定**：ECPFL 10/12 组（MNIST/FMNIST/CIFAR-10 三变体 + SVHN-UN，今日重跑）；ESAFL 的 N_up/N_agg（由 T=2 打包协议决定，与精度无关）
  - **ECPFL 行的 50 轮口径验算（以 MNIST-RK 为例）**：每轮上行 = 25 个投票密文（25×31.2KB=0.78MB）+ 共识入选的 k=2 个 pack × 25 客户端（50×31.2KB=1.56MB）≈ **2.34 MB/轮 × 50 轮 = 117.1 MB = 表中 UV**（json `total_upload_mb` 与逐轮求和逐位一致）。UV/FV/PV/TV/UT/DT/TT 全部为 50 轮累计，无遗漏。

| 方案 | 公式 | 实测来源 |
|---|---|---|
| FedAvg+CKKS / FedPHE | 理论 = 2 多项式 × 8192 系数 × 模数链 200 bit / 8 = 409,600 B；SEAL 序列化（zlib 压缩，压缩率 0.82）后 = **334,399 B** | `ct.serialize()` 现场实测；与基线 metrics `ciphertext_size/num_ciphertexts` 反推值 334,287 B 一致（±0.03%，序列化头部差异） |
| MASER xMK | 密文/份额均为 **pickle.dumps() 实测**（含多密钥结构）；聚合密文 = 单密文 × (N+1)/2（线性插值端点实测：N=25 → 13.0×） | `xMKCKKSManager(num_clients=25, slot_size=4096)` 初始化自检（encryptFromPk / addCTs / partialDecrypt 后序列化） |
| ESAFL / ECPFL | **n × log₂Q / 8** = 4096 × 61 / 8 = 31,232 B——只传 1 个多项式的系数；c1/mask 由 PRPG 种子本地再生，不占带宽；内存 CRT 双 int64 表示（16 B/系数）不计入线上大小 | `PurePyESHE.encrypt().coeffs_nbytes()` 与 ECPFL `ct_coeff_bytes = n*Q.bit_length()//8` 双路实测，逐字节一致 |

**结构性结论**：五方案单密文载荷相同（4,096 值），大小比 = 81.6 : 438.4(+份额) : 7.625 B/值 → ESHE 两个方案（ECPFL/ESAFL）对 SK-CKKS 基线 10.7×、对 xMK-CKKS 上行 57.5×/值。差距来源：①上传多项式个数（ESHE 1 个 vs CKKS/xMK 2 个，×2）；②模数位宽（61-bit 单素数 vs 200-bit 深链 / xMK 多密钥模数，×2.7~6.9）；③稀疏化（ζ/top-k）只能减密文个数、动不了单密文大小。

## 通信公平对比的参数设置原则（三档严格度）

**第一档（当前采用）：统一实验环境 + 各方案原生密码参数（"部署成本对比"）**
- 统一：N=25（全参与）、T=50、Dirichlet α=1 划分、相同模型/数据集/batch、带宽模拟器（异构带宽、最慢客户端计时）、MB=10⁶ 口径、TV=UV+FV、TT=Σₜ maxᵢ(训练+投票+加密+UT+DT)、每密文载荷 4,096 值对齐
- 密码参数：各方案用其论文/官方实现的原生参数——TenSEAL n=8192/[60,40,40,60]（SEAL λ=128 预算 218-bit 内 ✓）；ESHE n=4096/Q=61-bit（预算 109-bit 内 ✓，同 λ=128 档）；MASER xMK 用官方库默认参数（其自身安全性）
- 公平性锚点：**同安全档位（λ≥128）下的每值字节成本**。需补：Albrecht estimator 给 (n=4096, q≈2⁶¹, ternary/CB) 的 λ 具体数值写进正文
- 已知偏差须声明：ESAFL 参数轻量化（对 ESAFL 本身小模型有利/大模型不利，见前节交叉分析）；FedPHE 无成对掩码；MASER 与其它方案不同 N（原论文 N=9）

**第二档：统一环维度与载荷（"同 n 对比"）**
- ECPFL/ESAFL 换 n=8192（Q 仍 61-bit）：单密文 62,464 B、8,192 值/ct、J 减半（6/5/34/58）、投票密文翻倍——总 UV 仅因 padding 微涨 0~9%，但与基线同 n=8192，表格更对齐；加密耗时约 ×2.2
- 适合作为敏感性分析附录，证明结论对 n 不敏感

**第三档：对齐原论文密码参数（"论文口径敏感性"）**
- ESAFL 用 n=32768/Q=2⁴⁷⁸（单密文 1.96 MB、622,592 值/ct → 四数据集全部 1 ct/客户端）：MNIST UV 反而 ×5.7，CIFAR/SVHN 更省——证明"ESHE 优于 SK-CKKS 基线"的结论方向对参数稳健
- MASER 用原论文 N 与模型；FedPHE 补 Paillier 口径或成对掩码
- 工作量大，建议仅在 rebuttal 需要时补单数据集验证
