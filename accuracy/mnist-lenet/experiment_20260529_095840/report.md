### 5.3 Prefetch Communication Analysis / 预取通信分析

- **Total Upload / 总上传开销:** 3275.71 MB — 所有选中客户端密文上传的累计量
- **Fetch Volume (FV) / 补下载量:** 37.71 MB — 选中客户端实际 fetch 下载量（已扣除预取覆盖部分）
- **Training Communication (TV) / 训练通信:** 3313.42 MB = Upload(3275.71 MB) + FV(37.71 MB)
  ✅ 验证通过: Upload(3275.71 MB) + FV(37.71 MB) = TV(3313.42 MB)
  — TV 对齐 FedFetch 论文定义：TV = Upload + FV（不含后台预取）
- **Prefetch Broadcast / 预取广播:** 4376.50 MB — 服务器向未选中客户端后台广播的密文增量
- **Prefetch Download / 预取下载:** 4376.50 MB — 未选中客户端后台接收的密文增量
- **Prefetch + Fetch + Broadcast / 后台总流量:** 8790.71 MB = Prefetch DL(4376.50) + Fetch DL(37.71) + Broadcast(4376.50)
- **Effective Download / 理论下载责任:** 211.84 MB — 每轮 delta_size × 选中客户端数（预取节省率计算基准）
- **Prefetch Savings / 预取节省:** 174.13 MB — Effective Download 与实际 FV 的差值
- **Baseline (no prefetch) / 无预取基线:** 211.84 MB — 完整模型下载(0.17 MB × 1250 次)

> **Note / 说明:**
> 1. **FV** = 选中客户端实际 fetch 下载量。TV = Upload + FV（FedFetch 论文定义）。
> 2. **Effective Download** = delta_size × 选中客户端数，是理论下载责任，仅用于计算预取节省率。
> 3. **Prefetch** = 后台/空闲时流量，不计入 TV，但计入物理总下行带宽。
> 4. 预取的核心优势是**将训练前的同步下载变为后台增量推送**，降低 wall-clock 延迟。
